## Advanced Beam Patterns

### 1. **Side Inputs (Broadcast Join)**

Pass auxiliary data to transform functions.

```python
from apache_beam import Pipeline, Create, FlatMap, AsDict, AsIter
import apache_beam as beam

# Main data stream (events)
events = [
    {'user_id': '1', 'action': 'click'},
    {'user_id': '2', 'action': 'view'},
]

# Side input data (user metadata)
users = [
    {'id': '1', 'name': 'Alice', 'country': 'US'},
    {'id': '2', 'name': 'Bob', 'country': 'UK'},
]

with Pipeline() as p:
    # Create PCollections
    events_pc = p | 'CreateEvents' >> Create(events)
    users_pc = p | 'CreateUsers' >> Create(users)
    
    # Convert users to dictionary
    users_dict = (users_pc 
        | 'UserDict' >> beam.Map(lambda u: (u['id'], u))
        | 'AsDict' >> AsDict()
    )
    
    # Enrich events with user data
    def enrich_event(event, user_dict):
        user_data = user_dict.get(event['user_id'], {})
        event.update(user_data)
        return event
    
    enriched = (events_pc
        | 'Enrich' >> beam.Map(
            enrich_event,
            user_dict=beam.pvalue.AsSingleton(users_dict)
        )
    )

# Use case: Join small reference table with large stream
# Without side input: requires shuffle join (expensive)
# With side input: broadcast reference data to all workers
```

### 2. **Custom DoFn with Setup/Teardown**

Initialize expensive resources once per worker.

```python
class EnrichWithDatabase(beam.DoFn):
    """EnrichFn that connects to database"""
    
    def setup(self):
        """Called once per worker at startup"""
        print("Setting up database connection")
        import psycopg2
        
        self.conn = psycopg2.connect(
            host='db.example.com',
            database='metadata',
            user='user',
            password='password'
        )
        self.cursor = self.conn.cursor()
    
    def process(self, element):
        """Process element with initialized resource"""
        user_id = element['user_id']
        
        # Query database
        self.cursor.execute(
            'SELECT name, country FROM users WHERE id = %s',
            (user_id,)
        )
        row = self.cursor.fetchone()
        
        if row:
            element['name'], element['country'] = row
        
        yield element
    
    def teardown(self):
        """Called once per worker at shutdown"""
        print("Tearing down database connection")
        self.conn.close()

# Usage
enriched = events | beam.ParDo(EnrichWithDatabase())

# Benefits:
# - Connection opened once per worker, not per element
# - If 10K elements processed by worker, 1 connection (vs. 10K)
# - Much faster than per-element I/O
```

### 3. **Caching & Stateful Processing**

```python
from beam_nuggets.io import redisio
import redis

class CachedLookup(beam.DoFn):
    """Lookup with caching"""
    
    def setup(self):
        self.cache = {}
        self.db = redis.Redis(host='localhost', port=6379)
    
    def process(self, element):
        key = element['user_id']
        
        # Check in-memory cache first
        if key in self.cache:
            cached_data = self.cache[key]
        else:
            # Check Redis cache
            cached_data = self.db.get(key)
            if not cached_data:
                # Miss: fetch from database
                cached_data = fetch_from_database(key)
                # Update Redis
                self.db.setex(key, 3600, cached_data)
            # Update in-memory cache
            self.cache[key] = cached_data
        
        element['cached_data'] = cached_data
        yield element
    
    def teardown(self):
        self.db.close()

# Usage
results = events | beam.ParDo(CachedLookup())

# Performance:
# - Without cache: 1M events × DB latency (100ms) = 100K seconds
# - With cache (90% hit): 100K events × DB latency + 900K cache hits (1ms) = Much faster
```

### 4. **External Services / Side Outputs**

```python
class CallExternalAPI(beam.DoFn):
    """Call external API with error handling"""
    
    def process(self, element):
        import requests
        
        try:
            response = requests.post(
                'https://api.example.com/enrich',
                json=element,
                timeout=5
            )
            
            if response.status_code == 200:
                enriched = element
                enriched.update(response.json())
                yield enriched
            else:
                # API error: send to dead-letter
                yield beam.pvalue.TaggedOutput(
                    'api_error',
                    {**element, 'error_code': response.status_code}
                )
        
        except requests.Timeout:
            yield beam.pvalue.TaggedOutput(
                'api_timeout',
                element
            )
        except Exception as e:
            yield beam.pvalue.TaggedOutput(
                'api_exception',
                {**element, 'error': str(e)}
            )

# Usage with error handling
results = (events
    | beam.ParDo(CallExternalAPI()).with_outputs(
        'success',
        api_error='api_error',
        api_timeout='api_timeout',
        api_exception='api_exception'
    )
)

success = results.success
errors = results.api_error | 'WriteErrors' >> beam.io.WriteToText('gs://bucket/errors')
timeouts = results.api_timeout | 'WriteTimeouts' >> beam.io.WriteToText('gs://bucket/timeouts')
```

## State & Timers (Advanced Streaming)

### 1. **Per-Key State**

Maintain state for each key (e.g., per-user).

```python
from apache_beam.transforms.stateful import StatefulDoFn
from apache_beam.transforms.core import Stateful
from apache_beam.transforms.stateful import StatefulDoFnContext
import beam

class UserSessionAggregator(beam.DoFn):
    """Aggregate user session data with stateful processing"""
    
    # Define state variables
    USER_SESSION = 'user_session'
    
    def process(
        self,
        element,
        session_store=Stateful(USER_SESSION)
    ):
        user_id = element['user_id']
        action = element['action']
        timestamp = element['timestamp']
        
        # Read current state
        current_session = session_store.read()
        
        if current_session is None:
            # New session
            current_session = {
                'user_id': user_id,
                'start_time': timestamp,
                'actions': [action],
                'action_count': 1
            }
        else:
            # Extend existing session
            current_session['actions'].append(action)
            current_session['action_count'] += 1
        
        # Write back to state
        session_store.write(current_session)
        
        yield current_session

# Usage
sessions = (events
    | 'PerKey' >> beam.GroupByKey()
    | 'AggregateSession' >> beam.ParDo(UserSessionAggregator())
)

# Note: Requires Dataflow to maintain state across elements
# (not available in DirectRunner for testing)
```

### 2. **Timers (Delayed Execution)**

```python
from apache_beam.transforms.stateful import (
    StatefulDoFn,
    StatefulDoFnContext,
    TimestampType
)
from apache_beam.transforms.trigger import trigger_type

class TimeoutAggregator(beam.DoFn):
    """Aggregate with timeout - emit incomplete sessions"""
    
    SESSION_STATE = 'session'
    SESSION_TIMER = 'session_timer'
    
    def process(
        self,
        element,
        ts=beam.DoFn.TimestampParam,
        window=beam.DoFn.WindowParam,
        session_state=Stateful(SESSION_STATE),
        session_timer=Stateful(SESSION_TIMER)
    ):
        user_id = element['user_id']
        action = element['action']
        
        # Read state
        session = session_state.read() or []
        session.append(action)
        session_state.write(session)
        
        # Set timer for 5 seconds from now
        session_timer.set(ts.add(5))
    
    def on_session_timer(
        self,
        timestamp,
        session_state=Stateful(SESSION_STATE),
        session_timer=Stateful(SESSION_TIMER)
    ):
        """Called when timer fires"""
        session = session_state.read()
        
        if session:
            # Emit result
            yield {
                'session': session,
                'timeout': True
            }
        
        # Clear state
        session_state.clear()
        session_timer.clear()

# Usage: Sessions close after 5 seconds of inactivity
sessions = (events
    | beam.GroupByKey()  # Per user
    | beam.ParDo(TimeoutAggregator())
)
```

## Performance Optimization

### 1. **Fusion & Combiner Lifting**

```python
# Automatic optimizations:

# Fusion: Combine consecutive ParDo transforms
original = (data
    | beam.ParDo(ParseJson())
    | beam.ParDo(FilterInvalid())
    | beam.ParDo(Transform1())
    | beam.ParDo(Transform2())
)

# Fused into single function by Dataflow:
# → One worker function instead of 4
# → No serialization between stages

# Combiner lifting: Move aggregation before shuffle
original = (data
    | beam.Map(lambda x: (x['key'], x['value']))
    | beam.GroupByKey()
    | beam.CombinePerKey(sum)
)

# Lifted:
# → Pre-combine on workers (partial sums)
# → Shuffle only partial results
# → Final combine at destination
# → Huge reduction in shuffle data
```

### 4. **Reducing Network Shuffle**

```python
# Avoid large shuffles: pre-filter & pre-aggregate

# BAD: Large shuffle
data | beam.Map(lambda x: (x['key'], x)) | beam.GroupByKey()
# Shuffles entire dataset

# GOOD: Pre-filter then aggregate
data | beam.Filter(lambda x: x['important']) \
     | beam.Map(lambda x: (x['key'], x['value'])) \
     | beam.CombinePerKey(lambda values: sum(values))
# Shuffles only important data, smaller values

# GOOD: Use Reshuffle for testing
# (don't use in production - causes unnecessary shuffle)
data | beam.Reshuffle() | beam.Map(...)
```

## Real-World Case Studies

### Case Study 1: Real-Time Event Processing (1M events/sec)

**Scenario**: Process user events for analytics, real-time ML features

```python
from apache_beam import Pipeline, Create, ParDo, FlatMap, Map, Filter
from apache_beam.io import ReadFromPubSub, WriteToBigQuery, WriteToText
from apache_beam.transforms import window
from apache_beam.options.pipeline_options import StandardOptions, DataflowPipelineOptions
import apache_beam as beam
import json

options = DataflowPipelineOptions()
options.view_as(StandardOptions).streaming = True
options.view_as(StandardOptions).project = 'my-project'

pipeline = Pipeline(options=options)

# Step 1: Read from Pub/Sub
events = (pipeline
    | 'ReadPubSub' >> ReadFromPubSub(
        topic='projects/my-project/topics/user_events'
    )
)

# Step 2: Parse & validate
def parse_event(raw_event):
    try:
        event = json.loads(raw_event)
        if 'user_id' not in event or 'event_type' not in event:
            raise ValueError("Missing required fields")
        return event
    except json.JSONDecodeError:
        raise ValueError("Invalid JSON")

parsed = (events
    | 'Parse' >> beam.Map(parse_event)
)

# Step 3: Filter valid events
valid = (parsed
    | 'Filter' >> beam.Filter(lambda e: e['event_type'] in ['click', 'view', 'purchase'])
)

# Step 4: Enrich with user data (side input)
def enrich(event, user_cache):
    user_data = user_cache.get(event['user_id'], {})
    event.update(user_data)
    return event

enriched = (valid
    | 'Enrich' >> beam.Map(enrich, user_cache=...) # side input
)

# Step 5: Real-time aggregation (1-minute windows)
real_time_agg = (enriched
    | 'Window' >> beam.WindowInto(window.FixedWindows(60))
    | 'CountByType' >> beam.Map(lambda e: (e['event_type'], 1))
    | 'GroupByKey' >> beam.GroupByKey()
    | 'Sum' >> beam.Map(lambda kv: {'event_type': kv[0], 'count': sum(kv[1])})
)

# Output 1: Real-time metrics to Pub/Sub
real_time_agg | 'PublishMetrics' >> beam.io.WriteToPubSub(
    topic='projects/my-project/topics/metrics'
)

# Output 2: All events to BigQuery
enriched | 'WriteEvents' >> beam.io.WriteToBigQuery(
    dataset='events',
    table='raw_events',
    schema='user_id:STRING,event_type:STRING,...'
)

pipeline.run().wait_until_finish()

# Performance:
# - 1M events/second → auto-scales to 100+ workers
# - Latency: Event to analytics: <1 second
# - Cost: $0.2-0.3/hour for 100 workers
```

    def process(self, element):
        record = json.loads(element)
        
        # Version-aware parsing

        if schema_version == 1:
            # Old schema: map to new
            record = {
                'id': record['old_id'],
                'name': record['old_name'],
                'version': 2  # Upgrade version
            }
        elif schema_version == 2:
            # Current schema
            pass
        else:
            # Unknown version - quarantine
            yield beam.pvalue.TaggedOutput('unknown_schema', record)
            return
        
        # Add metadata
        record['_ingestion_time'] = time.time()
        record['_processed'] = True
        
        yield record

pipeline = Pipeline(options=options)

## Interview Design Questions

### Q1: "Design a streaming pipeline processing 10M events/day with 30-minute SLA."

**Answer**:
1. **Source**: Cloud Pub/Sub (auto-scaling)
2. **Parsing**: Extract, validate, enrich
3. **Windowing**: 10-minute tumbling windows
4. **Aggregation**: Group by dimensions, compute metrics
5. **Sink**: BigQuery for analysis, Pub/Sub for real-time dashboards
6. **Monitoring**: Track watermark, lateness, error rate
7. **Scaling**: 10-50 workers based on load

### Q2: "Handle 10 million user IDs in reference data. How to enrich 1B events/day?"

**Answer**:
- **Don't ship all 10M to every worker** (memory issues)
- **Options**:
  1. **Side input**: Broadcast reference table (if <1GB)
  2. **Database join**: Stateful DoFn with connection pooling
  3. **Cloud Bigtable**: Fast key-value lookups
  4. **Shuffle join**: If both datasets large
- **Chosen**: Stateful DoFn with Bigtable (fast, scales)

### Q3: "Dataflow job takes 4 hours but needs to complete in 1 hour."

**Answer**:
1. **Profile**: Identify bottleneck (parse? shuffle? write?)
2. **Parallelize**: Increase workers/parallelism
3. **Optimize DoFn**: Use caching, batch operations
4. **Reduce shuffle**: Pre-aggregate, pre-filter
5. **Optimize I/O**: BigQuery streaming vs. batch load
6. **Cost**: Faster = more workers = higher cost, tradeoff
