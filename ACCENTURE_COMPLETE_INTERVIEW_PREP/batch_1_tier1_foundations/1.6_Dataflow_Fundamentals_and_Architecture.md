## Introduction & Architecture

### What is Dataflow?

Cloud Dataflow is Google Cloud's **fully managed service for batch and streaming data processing**. Built on **Apache Beam**, it abstracts away infrastructure complexity:

```
User Code (Python/Java)
        ↓ (Apache Beam API)
Portable Pipeline (language-agnostic)
        ↓ (Dataflow Runner)
Distributed Execution (auto-scaling workers)
```

### Historical Context

**MapReduce** (2004): Google's batch processing framework
- Dominated big data for a decade
- Two-stage model: Map → Shuffle → Reduce

**Apache Spark** (2014): In-memory distributed computing
- Faster than MapReduce
- Better DAG abstraction

**Apache Beam** (2016): Google's unified model for batch + streaming
- Developed by Google, open-sourced
- "Write once, run anywhere" philosophy
- Supports multiple runners: Dataflow, Spark, Flink, etc.

**Cloud Dataflow**: Google's managed Beam runner

### Why Dataflow?

| Aspect | Benefit |
|--------|---------|
| **Unified Batch/Stream** | Same code for both (temporal processing) |
| **Auto-scaling** | Workers scale based on load |
| **Serverless** | No infrastructure management |
| **Integration** | Native GCP service integration |
| **Cost-efficient** | Pay per resource-second, auto-shutdown |

## Apache Beam Programming Model

### Core Concept: What is a Beam Pipeline?

A **Pipeline** is a Directed Acyclic Graph (DAG) representing:
- **Data sources** (Read)
- **Transformations** (Process)
- **Sinks** (Write)

```python
from apache_beam import Pipeline
from apache_beam.options.pipeline_options import PipelineOptions, StandardOptions
from apache_beam.io import ReadFromText, WriteToText
import apache_beam as beam

# Create pipeline
options = PipelineOptions()
options.view_as(StandardOptions).runner = 'DataflowRunner'

with Pipeline(options=options) as p:
    # Source: Read from GCS
    lines = p | 'ReadText' >> ReadFromText('gs://my-bucket/input.txt')
    
    # Transform: Split, filter, map
    words = (lines 
            | 'Split' >> beam.FlatMap(lambda x: x.split())
            | 'Filter' >> beam.Filter(lambda w: len(w) > 3)
            | 'Uppercase' >> beam.Map(lambda w: w.upper()))
    
    # Sink: Write to GCS
    words | 'WriteText' >> WriteToText('gs://my-bucket/output.txt')

# When pipeline executes:
# 1. Dataflow compiles to execution graph
# 2. Submits to Google Cloud
# 3. Auto-scales workers
# 4. Executes transforms
# 5. Returns results
```

### Pipeline vs. PipelineResult

```python
from apache_beam.runners.dataflow.dataflow_runner import DataflowRunner

# Option 1: Context manager (blocking)
with Pipeline(options=options) as pipeline:
    # Define transforms
    pass
# Pipeline blocks until completion

# Option 2: Explicit execution (non-blocking)
pipeline = Pipeline(options=options)
# Define transforms
result = pipeline.run()  # Returns immediately

# Wait for completion
result.wait_until_finish()

# Check result
if result.state == beam.runners.runner.PipelineState.DONE:
    print("Success")
elif result.state == beam.runners.runner.PipelineState.FAILED:
    print("Failed")
```

## Core Concepts: PCollections, Transforms, Windows

### 1. **PCollection (Parallel Collection)**

An immutable, distributed dataset that can be processed in parallel.

```python
from apache_beam import Pipeline, Create
import apache_beam as beam

# Create PCollection from in-memory data
with Pipeline() as p:
    # PCollection with 3 elements
    numbers = p | 'Create' >> Create([1, 2, 3, 4, 5])
    
    # Each element processed independently and in parallel
    squares = numbers | 'Square' >> beam.Map(lambda x: x**2)

# PCollection properties:
# - Immutable: Cannot modify elements
# - Distributed: Elements scattered across workers
# - Typed: Can have schema (explicit types)
# - Lazy: No execution until pipeline runs

# Bounded vs. Unbounded:
# - Bounded: Finite (batch data from GCS)
# - Unbounded: Infinite (streaming from Pub/Sub)
```

### 2. **Transforms (ParDo, Map, FlatMap, Filter)**

Operations that transform PCollections.

```python
import apache_beam as beam

# Transform 1: Map (element-wise transformation)
numbers = ... # PCollection of [1, 2, 3]
squares = numbers | beam.Map(lambda x: x**2)
# Result: [1, 4, 9]

# Transform 2: FlatMap (1→N mapping)
words = ... # ['hello world', 'apache beam']
letters = words | beam.FlatMap(lambda w: list(w))
# Result: ['h', 'e', 'l', 'l', 'o', 'w', ...]

# Transform 3: Filter
numbers = [1, 2, 3, 4, 5]
evens = numbers | beam.Filter(lambda x: x % 2 == 0)
# Result: [2, 4]

# Transform 4: ParDo (Parallel Do)
# Most general transform, equivalent to Map
class MultiplyByTwo(beam.DoFn):
    def process(self, element):
        yield element * 2

result = numbers | beam.ParDo(MultiplyByTwo())

# Key-Value transforms
pairs = ... # [('a', 1), ('b', 2), ('a', 3)]

# GroupByKey: Group by key
grouped = pairs | beam.GroupByKey()
# Result: [('a', [1, 3]), ('b', [2])]

# CoGroupByKey: Join two PCollections by key
pc1 = [('a', 1), ('b', 2)]
pc2 = [('a', 10), ('b', 20), ('c', 30)]
joined = (
    {'pc1': pc1, 'pc2': pc2}
    | beam.CoGroupByKey()
)
# Result: ('a', {'pc1': [1], 'pc2': [10]}), ('b', {'pc1': [2], 'pc2': [20]}), ...
```

### 3. **ParDo (Custom Transforms)**

For complex transformations requiring state or side outputs.

```python
class ParseEvent(beam.DoFn):
    """Parse JSON event"""
    
    def process(self, element):
        try:
            import json
            event = json.loads(element)
            
            # Validation
            if 'event_id' not in event:
                yield beam.pvalue.TaggedOutput('invalid', element)
                return
            
            # Main output
            yield event
            
        except json.JSONDecodeError as e:
            # Side output for errors
            yield beam.pvalue.TaggedOutput('parse_error', element)

# Use ParDo with side outputs
events = ... # PCollection of JSON strings

results = events | beam.ParDo(ParseEvent()).with_outputs(
    'valid',  # Default output
    invalid='invalid',
    parse_error='parse_error'
)

valid_events = results.valid
invalid_events = results.invalid
errors = results.parse_error

# Use different outputs in pipeline
valid_events | 'ProcessValid' >> beam.Map(lambda e: e['event_id'])
invalid_events | 'ReprocessInvalid' >> beam.ParDo(RetryParse())
errors | 'LogErrors' >> beam.ParDo(LogErrorFn())
```

### 4. **Aggregations & Grouping**

```python
import apache_beam as beam

# GroupByKey (shuffle-based aggregation)
pairs = [('a', 1), ('a', 2), ('b', 3), ('b', 4), ('b', 5)]
grouped = pairs | beam.GroupByKey()
# Result: [('a', [1, 2]), ('b', [3, 4, 5])]

# Combine (associative aggregation)
grouped | beam.CombinePerKey(sum)
# Result: [('a', 3), ('b', 12)]

# Custom combine function
from apache_beam.transforms.combiners import Sum, Mean

# Sum all values
numbers = [1, 2, 3, 4, 5]
total = numbers | 'Sum' >> beam.CombineGlobally(sum)
# Result: [15]

# Mean
mean = numbers | 'Mean' >> beam.CombineGlobally(beam.transforms.combiners.MeanCombineFn())

# Top-K elements
class TopKCombineFn(beam.CombineFn):
    def create_accumulator(self):
        return []
    
    def add_input(self, acc, elem):
        acc.append(elem)
        acc.sort(reverse=True)
        return acc[:10]  # Keep top 10
    
    def merge_accumulators(self, accs):
        merged = []
        for acc in accs:
            merged.extend(acc)
        merged.sort(reverse=True)
        return merged[:10]
    
    def extract_output(self, acc):
        return acc

top_k = numbers | beam.CombineGlobally(TopKCombineFn())
```

### 5. **Windowing (Time-Based Aggregation)**

Dividing unbounded streams into finite windows for aggregation.

```python
from apache_beam.transforms.window import Window, FixedWindows, SlidingWindows, SessionWindows
import apache_beam as beam

# Fixed Windows: Divide into fixed-size buckets
windowed = (events 
    | 'Fixed 60s Windows' >> Window(FixedWindows(60))
    | 'Count per window' >> beam.CombineGlobally(len).without_defaults()
)
# Events grouped into 60-second buckets

# Sliding Windows: Overlapping windows
windowed = (events
    | 'Sliding 60s Windows (30s step)' >> Window(
        SlidingWindows(size=60, period=30)
    )
)
# Each event in multiple windows (overlap)

# Session Windows: Group by activity
windowed = (events
    | 'Session Windows (5min gap)' >> Window(
        SessionWindows(gap_duration=5*60)
    )
)
# Events with <5min gap grouped together

# Windowing with GroupByKey
def count_per_window(elements):
    return len(list(elements))

counts = (events
    | Window(FixedWindows(60))
    | beam.Map(lambda e: (e['user_id'], 1))
    | beam.GroupByKey()
    | beam.Values()
    | beam.Map(lambda v: sum(v))
)

# Allowed Lateness: How late can data arrive?
from apache_beam.transforms.trigger import AfterWatermark, OrFinally, AfterCount

windowed = (events
    | 'Windows with lateness' >> Window(
        FixedWindows(60),
        allowed_lateness=120,  # Accept data 2min late
        trigger=AfterWatermark(
            early=None,  # No early pane
            late=AfterCount(1)  # Emit on each late element
        )
    )
)
```

### 6. **Triggers (Advanced Windowing)**

Control when windows emit results.

```python
from apache_beam.transforms.trigger import (
    AfterWatermark, OrFinally, AfterCount, AfterProcessingTime
)
import apache_beam as beam

# Trigger 1: After watermark (when input complete)
trigger1 = AfterWatermark(
    early=None,  # No early output
    late=AfterCount(1)  # Emit on late data
)

# Trigger 2: After count
trigger2 = AfterCount(1000)  # Emit when 1000 elements in window

# Trigger 3: After processing time
trigger3 = AfterProcessingTime(60)  # Emit 60 seconds after window start

# Trigger 4: Composite (early, on-time, late)
trigger_composite = AfterWatermark(
    early=AfterCount(100),  # Early pane after 100 elements
    late=AfterProcessingTime(60)  # Late pane 60s after start
)

windowed = (events
    | 'Windows with triggers' >> Window(
        FixedWindows(60),
        allowed_lateness=300,
        trigger=trigger_composite
    )
)
```

## Dataflow Execution Engine

### 1. **Batch vs. Streaming Execution**

```python
from apache_beam.options.pipeline_options import StandardOptions

# BATCH: Process bounded data (default)
options = PipelineOptions()
options.view_as(StandardOptions).runner = 'DataflowRunner'

pipeline = Pipeline(options=options)
# Dataflow optimizes for throughput

# STREAMING: Process unbounded data
options = PipelineOptions()
options.view_as(StandardOptions).runner = 'DataflowRunner'
options.view_as(StandardOptions).streaming = True

pipeline = Pipeline(options=options)
# Dataflow optimizes for latency
```

### 2. **Dataflow Graph Compilation**

User code → Optimized execution graph

```python
from apache_beam.pipeline import Pipeline
from apache_beam.options.pipeline_options import PipelineOptions

pipeline = Pipeline()

# Original pipeline (multiple ParDo transforms)
pcoll = (
    pipeline
    | 'Read' >> beam.io.ReadFromText('input.txt')
    | 'ParDo1' >> beam.ParDo(MyDoFn1())
    | 'ParDo2' >> beam.ParDo(MyDoFn2())
    | 'ParDo3' >> beam.ParDo(MyDoFn3())
    | 'Write' >> beam.io.WriteToText('output.txt')
)

# Dataflow optimizes:
# 1. Fusion: Combines ParDo1, ParDo2, ParDo3 into single worker function
#    (avoids intermediate PCollection serialization)
# 2. Dead-code elimination: Removes unused transforms
# 3. Combiners lifting: Moves combiners before shuffle for efficiency

# Optimized graph:
# Read → [Fused: ParDo1+ParDo2+ParDo3] → Write
```

### 3. **Watermark & Event Time vs. Processing Time**

```python
from apache_beam.transforms.window import Window, FixedWindows
from apache_beam.transforms.core import WithTimestamps
import apache_beam as beam

# Event time: When event occurred
# Processing time: When system processes event
# Watermark: Progress of event time (how far ahead we've processed)

class AddTimestamp(beam.DoFn):
    def process(self, element):
        # Extract timestamp from event
        import json
        from datetime import datetime
        
        event = json.loads(element)
        ts = datetime.fromisoformat(event['timestamp'])
        
        yield beam.window.TimestampedValue(event, ts.timestamp())

# Pipeline with watermark-based windowing
events = (pipeline
    | 'ReadText' >> beam.io.ReadFromText('events.json')
    | 'AddTimestamp' >> beam.ParDo(AddTimestamp())
    | 'Window' >> Window(FixedWindows(60))
    | 'Count' >> beam.CombineGlobally(len).without_defaults()
)

# Watermark behavior:
# - Data arrives with event time
# - Watermark advances as system processes
# - When watermark passes window end: window closes
# - Late data (after watermark) can still arrive (allowed_lateness)
```

## Interview Questions

### Q1: "What's the difference between batch and streaming Dataflow?"

**Answer**:
- **Batch**: Bounded data (starts/ends), optimize for throughput
  - Use case: ETL from GCS/BigQuery
  - Watermark advances when all data processed
  - Cost: Lower (no standby charges)
- **Streaming**: Unbounded data (infinite), optimize for latency
  - Use case: Real-time from Pub/Sub
  - Watermark advances continuously
  - Cost: Higher (always running, standby charges)
  - Must handle late/out-of-order data

### Q2: "How to handle out-of-order events in Dataflow?"

**Answer**:
1. **Extract timestamp**: Use event_time from data, not processing_time
2. **Windowing**: Group by event_time window (60-second buckets)
3. **Watermark**: System tracks progress of event_time
4. **Allowed lateness**: Accept events arriving up to N seconds late
5. **Trigger logic**: Define when to emit window results

```python
| Window(FixedWindows(60), allowed_lateness=300)
```

### Q3: "Design a streaming ETL pipeline for 1M events/second."

**Answer**:
- **Source**: Cloud Pub/Sub (scales to millions)
- **Parse**: Extract timestamp, validate schema
- **Enrich**: Join with reference data (BigTable)
- **Window**: 60-second buckets by user
- **Aggregate**: Count, distinct, percentiles
- **Sink**: BigQuery for analysis, Pub/Sub for real-time
- **Parallelism**: Auto-scale 100+ workers
- **Monitoring**: Dataflow metrics, lag, errors
