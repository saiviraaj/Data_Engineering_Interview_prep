## Introduction & Data Quality Dimensions

### What is Data Quality?

**Data Quality** = Fitness of data for its intended use

Not: "Data is clean"
But: "Data meets business requirements for this analysis"

### Six Dimensions of Data Quality

```
┌─────────────────────────────────────┐
│    SIX DATA QUALITY DIMENSIONS      │
├─────────────────────────────────────┤
│ 1. ACCURACY      - Values match     │
│    reality / source of truth        │
│                                     │
│ 2. COMPLETENESS  - No missing       │
│    values, sufficient coverage      │
│                                     │
│ 3. CONSISTENCY   - Same data        │
│    represented uniformly across     │
│    systems                          │
│                                     │
│ 4. TIMELINESS    - Data fresh,      │
│    updated at required frequency    │
│                                     │
│ 5. VALIDITY      - Data conforms    │
│    to required schema/format        │
│                                     │
│ 6. UNIQUENESS    - No unintended    │
│    duplicates                       │
└─────────────────────────────────────┘
```

### Cost of Poor Data Quality

**Direct Costs**:
- Rework (fixing errors)
- Failed analytical projects
- Incorrect business decisions

**Indirect Costs**:
- Wasted analyst time (debugging)
- Lost trust in data platforms
- Regulatory penalties (compliance failures)

**Industry Data**: Poor data quality costs organizations **$15M+ annually** (average Fortune 500)

## Data Quality Frameworks

### 1. **Great Expectations Framework**

Open-source Python library for automated data validation.

```python
import great_expectations as ge
from great_expectations.core.batch import RuntimeBatchRequest
from great_expectations.validator import Validator

# Load data
df = ge.read_csv('data.csv')

# Create expectations (data contracts)
expectations = [
    # Column exists
    df.expect_column_to_exist('user_id'),
    
    # Uniqueness: No duplicates
    df.expect_column_values_to_be_unique('user_id'),
    
    # Type validation
    df.expect_column_values_to_be_of_type('user_id', 'object'),
    df.expect_column_values_to_be_of_type('signup_date', 'datetime64[ns]'),
    
    # Range validation
    df.expect_column_values_to_be_between('age', min_value=0, max_value=150),
    
    # Pattern validation (regex)
    df.expect_column_values_to_match_regex('email', r'^[\w\.-]+@[\w\.-]+\.\w+$'),
    
    # Null check
    df.expect_column_values_to_not_be_null('user_id'),
    df.expect_column_values_to_not_be_null('email'),
    
    # Subset validation
    df.expect_column_values_to_be_in_set('country', ['US', 'UK', 'CA', 'IN']),
    
    # Statistical validation
    df.expect_column_median_to_be_between('salary', min_value=30000, max_value=200000),
    
    # Custom validation
    df.expect_table_row_count_to_be_between(min_value=1000, max_value=1000000)
]

# Validate
validation_results = df.validate()

# Report
print(f"Passed: {validation_results.statistics['evaluated_expectations']}")
print(f"Failed: {validation_results.statistics['unsuccessful_expectations']}")

if not validation_results.success:
    print(validation_results)
```

### 4. **Reconciliation Testing**

Validate data consistency across systems.

```python
from google.cloud import bigquery

def reconcile_data_sources():
    """Compare data between source and warehouse"""
    client = bigquery.Client(project='my-project')
    
    # Source query (e.g., operational database)
    source_query = """
    SELECT 
        COUNT(*) as row_count,
        COUNT(DISTINCT user_id) as unique_users,
        SUM(amount) as total_amount,
        MIN(created_at) as earliest_date,
        MAX(created_at) as latest_date
    FROM operational_db.orders
    """
    
    # Warehouse query
    warehouse_query = """
    SELECT 
        COUNT(*) as row_count,
        COUNT(DISTINCT user_id) as unique_users,
        SUM(amount) as total_amount,
        MIN(created_at) as earliest_date,
        MAX(created_at) as latest_date
    FROM my_project.analytics_prod.orders
    """
    
    source_results = client.query(source_query).to_dataframe()
    warehouse_results = client.query(warehouse_query).to_dataframe()
    
    # Compare
    differences = source_results.compare(warehouse_results)
    
    if not differences.empty:
        print("Reconciliation failed!")
        print(differences)
        # Alert team
        send_alert("Data reconciliation failed")
    else:
        print("✓ Data reconciliation passed")

# Run daily via Cloud Scheduler
reconcile_data_sources()
```

### 3. **Statistical Anomaly Detection**

Identify unusual patterns using statistics.

```python
import pandas as pd
from scipy import stats
import numpy as np

def detect_anomalies(data: pd.DataFrame, column: str, threshold: float = 3.0):
    """Detect statistical anomalies using Z-score"""
    
    # Calculate Z-scores (distance from mean in std devs)
    z_scores = np.abs(stats.zscore(data[column]))
    
    # Flag outliers (Z-score > threshold)
    anomalies = data[z_scores > threshold]
    
    return anomalies

# Example: Daily user counts
daily_data = pd.DataFrame({
    'date': pd.date_range('2024-01-01', periods=30),
    'user_count': [1000, 1050, 980, 1100, 95, 1090, 1020, ...]  # 95 is anomaly
})

anomalies = detect_anomalies(daily_data, 'user_count', threshold=2.5)
print(f"Anomalies detected: {len(anomalies)}")
# Output: Anomalies detected: 1 (the day with 95 users)

# BigQuery version (using percentiles)
query = """
WITH daily_counts AS (
  SELECT 
    DATE(created_at) as date,
    COUNT(*) as user_count
  FROM events
  WHERE created_at >= DATE_SUB(CURRENT_DATE(), INTERVAL 30 DAY)
  GROUP BY date
),
stats AS (
  SELECT
    APPROX_QUANTILES(user_count, 100)[OFFSET(25)] as q25,
    APPROX_QUANTILES(user_count, 100)[OFFSET(75)] as q75
  FROM daily_counts
)
SELECT
  d.date,
  d.user_count,
  CASE 
    WHEN d.user_count < s.q25 * 0.5 OR d.user_count > s.q75 * 1.5 THEN 'ANOMALY'
    ELSE 'NORMAL'
  END as status
FROM daily_counts d
CROSS JOIN stats s
ORDER BY d.date DESC;
"""
```

## Monitoring & Alerting

### 1. **Data Quality Dashboard**

```sql
-- BigQuery view: Real-time data quality metrics
CREATE OR REPLACE VIEW my_project.analytics_prod.vw_data_quality_metrics AS

WITH daily_quality AS (
  SELECT
    DATE(processed_timestamp) as quality_date,
    source_system,
    
    -- Completeness
    COUNT(*) as total_records,
    COUNTIF(event_id IS NULL) as null_event_ids,
    ROUND(1 - COUNTIF(event_id IS NULL) / COUNT(*), 4) as completeness,
    
    -- Uniqueness
    COUNT(DISTINCT event_id) as unique_events,
    ROUND(COUNT(DISTINCT event_id) / COUNT(*), 4) as uniqueness,
    
    -- Timeliness (data freshness)
    MIN(DATE_DIFF(CURRENT_TIMESTAMP(), processed_timestamp, HOUR)) as oldest_data_hours,
    
    -- Validity (schema conformance)
    COUNTIF(JSON_EXTRACT_SCALAR(raw_data, '$.event_type') IN 
      ('click', 'view', 'purchase', 'scroll')) as valid_event_types,
    
    -- Duplicate detection
    COUNT(*) - COUNT(DISTINCT event_id) as duplicate_count
    
  FROM my_project.raw_prod.events_raw
  WHERE processed_timestamp >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 24 HOUR)
  GROUP BY quality_date, source_system
)

SELECT
  quality_date,
  source_system,
  total_records,
  completeness,
  uniqueness,
  oldest_data_hours,
  duplicate_count,
  CASE 
    WHEN completeness < 0.95 THEN 'FAILED'
    WHEN uniqueness < 0.99 THEN 'FAILED'
    WHEN oldest_data_hours > 12 THEN 'FAILED'
    WHEN duplicate_count > total_records * 0.01 THEN 'FAILED'
    ELSE 'PASSED'
  END as quality_status
FROM daily_quality
ORDER BY quality_date DESC, quality_status;
```

```python
from google.cloud import monitoring_v3
from google.cloud.monitoring.alert import NotificationChannelSeverity

def create_data_quality_alert():
    """Create alert for data quality failures"""
    
    client = monitoring_v3.AlertPolicyServiceClient()
    project_name = client.project_path('my-project')
    
    # Alert condition: Completeness < 95%
    alert_policy = monitoring_v3.AlertPolicy(

            monitoring_v3.AlertPolicy.Condition(
                display_name='Completeness threshold',
                condition_threshold=monitoring_v3.AlertPolicy.Condition.MetricThreshold(
                    filter_='resource.type="bigquery_table" AND '
                            'metric.type="custom.googleapis.com/data_quality/completeness" AND '
                            'resource.label.table_name="events"',
                    comparison=monitoring_v3.ComparisonType.COMPARISON_LT,
                    threshold_value=0.95,  # <95%
                    duration=monitoring_v3.Duration(seconds=300),  # 5 min
                    aggregations=[
                        monitoring_v3.Aggregation(
                            alignment_period=monitoring_v3.Duration(seconds=60),
                            per_series_aligner=monitoring_v3.Aggregation.Aligner.ALIGN_MEAN,
                        )
                    ]
                )
            )
        ],
        notification_channels=[
            'projects/my-project/notificationChannels/channel-id'  # Slack/Email/PagerDuty
        ]
```

### 3. **Data Freshness Monitoring**

```sql
-- Check data lag (how fresh is data?)
CREATE OR REPLACE PROCEDURE `my_project.analytics_prod.sp_check_data_freshness`()
BEGIN
  DECLARE fresh_threshold_hours INT64 DEFAULT 24;
  
  -- Check freshness for each critical table
  WITH freshness_check AS (
    SELECT
      'events' as table_name,
      MAX(processed_timestamp) as latest_data_time,
      TIMESTAMP_DIFF(CURRENT_TIMESTAMP(), MAX(processed_timestamp), HOUR) as hours_stale
    FROM `my_project.raw_prod.events`
    
    UNION ALL
    
    SELECT
      'users' as table_name,
      MAX(updated_at),
      TIMESTAMP_DIFF(CURRENT_TIMESTAMP(), MAX(updated_at), HOUR)
    FROM `my_project.analytics_prod.users`
  )
  SELECT *
  FROM freshness_check
  WHERE hours_stale > fresh_threshold_hours;
  
  -- If result set non-empty: data is stale, trigger alert
END;

-- Schedule: Every 2 hours
-- Alert: If any table > 24 hours old
```

```python
from airflow.operators.python import PythonOperator
from airflow.providers.slack.operators.slack_webhook import SlackWebhookOperator
from datetime import datetime, timedelta
import great_expectations as ge

dag = DAG(
    'data_quality_validation',
    start_date=datetime(2024, 1, 1),
    schedule_interval='@hourly',
    default_args={'retries': 2}
)

def validate_events_table(**context):
    """Validate events table quality"""
    client = bigquery.Client()
    
    # Load data
    query = """
    SELECT *
    FROM `my_project.raw_prod.events`
    WHERE DATE(processed_timestamp) = CURRENT_DATE()
    LIMIT 100000
    """
    df = client.query(query).to_pandas()
    
    # Create great_expectations context
    ge_df = ge.from_pandas(df)
    
    # Run expectations
    expectations = [
        ge_df.expect_column_values_to_not_be_null('event_id'),
        ge_df.expect_column_values_to_be_unique('event_id'),
        ge_df.expect_column_values_to_be_in_set('event_type', ['click', 'view', 'purchase']),
    ]
    
    # Store result
    results = ge_df.validate()
    context['task_instance'].xcom_push(
        key='validation_results',
        value=results.to_json_dict()
    )
    
    if not results.success:
        raise Exception(f"Data quality validation failed: {results}")

def send_quality_report(**context):
    """Send report to Slack"""
    ti = context['task_instance']
    results = ti.xcom_pull(task_ids='validate', key='validation_results')
    
    # Format report
    message = f"""
    Data Quality Report - {datetime.now().strftime('%Y-%m-%d %H:%M')}
    Validation: {'PASSED' if results['success'] else 'FAILED'}
    """
    
    # Send to Slack
    # (SlackWebhookOperator handles this)

validate_task = PythonOperator(
    task_id='validate',
    python_callable=validate_events_table,
    provide_context=True,
    dag=dag
)

# Alert on failure
alert_task = SlackWebhookOperator(
    task_id='alert_on_failure',
```

## Accenture Research Platform Design

### Data Quality Framework for 100+ Research Projects

```sql
-- Metadata table: Quality rules per project
CREATE TABLE `my_project.governance.data_quality_rules` (
  rule_id STRING,
  project_id STRING,
  dataset_name STRING,
  table_name STRING,
  
  -- Rule definition
  rule_name STRING,
  rule_description STRING,
  rule_type STRING,  -- null_check, uniqueness, range, pattern, etc.
  rule_sql STRING,
  
  -- Thresholds
  threshold_type STRING,  -- max_failures, max_failure_rate
  threshold_value NUMERIC,
  
  -- Scheduling
  check_frequency STRING,  -- daily, hourly, on_demand
  
  -- Ownership
  owner_email STRING,
  created_timestamp TIMESTAMP,
  modified_timestamp TIMESTAMP,
  is_active BOOL
)
CLUSTER BY project_id, dataset_name;

-- Track quality results
CREATE TABLE `my_project.governance.quality_check_results` (
  check_run_id STRING,
  rule_id STRING,
  project_id STRING,
  check_timestamp TIMESTAMP,
  
  -- Results
  rows_checked INT64,
  rows_failed INT64,
  failure_rate FLOAT64,
  
  -- Status
  status STRING,  -- PASS, FAIL, WARNING
  error_message STRING,
  
  -- Linked to investigation
  investigation_ticket_id STRING
)
PARTITION BY DATE(check_timestamp)
CLUSTER BY project_id, rule_id;

-- Create quality dashboard
CREATE OR REPLACE VIEW `my_project.governance.vw_project_quality_summary` AS
SELECT
  p.project_id,
  p.project_name,
  COUNT(DISTINCT CASE WHEN qr.status = 'PASS' THEN qr.rule_id END) as rules_passed,
  COUNT(DISTINCT CASE WHEN qr.status = 'FAIL' THEN qr.rule_id END) as rules_failed,
  ROUND(
    COUNT(DISTINCT CASE WHEN qr.status = 'PASS' THEN qr.rule_id END) / 
    COUNT(DISTINCT qr.rule_id),
    4
  ) as quality_score,
  CASE 
    WHEN COUNT(DISTINCT CASE WHEN qr.status = 'FAIL' THEN qr.rule_id END) > 0 THEN 'RED'
    WHEN COUNT(DISTINCT CASE WHEN qr.status = 'WARNING' THEN qr.rule_id END) > 0 THEN 'YELLOW'
    ELSE 'GREEN'
  END as status
FROM `my_project.governance.projects` p
LEFT JOIN `my_project.governance.quality_check_results` qr
  ON p.project_id = qr.project_id
  AND DATE(qr.check_timestamp) = CURRENT_DATE()
GROUP BY p.project_id, p.project_name;
```

## Interview Questions

### Q1: "Design a data quality framework for 100 daily data sources."

**Answer**:
1. **Expectations per source**: Define quality rules (schema, range, freshness)
2. **Automated validation**: dbt tests + Great Expectations
3. **Scoring**: Completeness %, uniqueness %, timeliness %
4. **Monitoring**: Dashboard + alerts for failing sources
5. **Remediation**: Workflow for data teams to fix issues
6. **Governance**: Ownership, SLAs per source

### Q2: "How to detect data quality issues automatically?"

**Answer**:
1. **Schema validation**: Columns match expected types
2. **Statistical**: Z-score for outliers, waterfall checks
3. **Referential integrity**: FK relationship checks
4. **Freshness**: Last update time monitoring
5. **Reconciliation**: Compare source vs. warehouse
6. **ML-based**: Anomaly detection for complex patterns

### Q3: "Data quality failed at 2 AM. Root cause in 5 minutes?"

**Answer**:
1. **Check ingestion logs**: Any errors parsing data?
2. **Source data**: Did source system have issues?
3. **Reconciliation**: Compare row counts source vs. warehouse
4. **Recent changes**: Was pipeline modified?
5. **Dependency check**: Did upstream table fail?
6. **Automate**: Alert with root cause analysis
