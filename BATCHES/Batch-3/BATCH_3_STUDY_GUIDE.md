## 📋 Practice Method

### Method 1: Timed Problem Solving

```
1. Set timer for 45 minutes
2. Read problem statement
3. Clarify requirements (2-3 min)
4. Propose high-level design (5-7 min)
5. Deep dive on components (20-25 min)
6. Handle failures (5-10 min)
7. Answer remaining questions (3-5 min)

After 45 minutes:
├─ STOP (even if not done)
├─ Read official solution
├─ Compare your approach
├─ Understand what you missed
```

### Method 2: Study Solutions Deeply

```
For each problem:
1. Read solution slowly (20-30 min)
2. Understand each decision (why PostgreSQL? why sharding?)
3. What trade-offs are mentioned?
4. How does it scale?
5. What could fail?
6. Could you code this? (not required, but think about it)
```

### Method 3: Variation Practice

```
Problem: Design for 100K requests/sec
Modified: Design for 1M requests/sec
├─ What changes?
├─ What bottleneck appears?
└─ How do you solve it?

Problem: Allow eventual consistency
Modified: Require strong consistency
├─ What's harder?
├─ What's the trade-off?
└─ Is it worth it?

Problem: Single region
Modified: Multi-region with low latency
├─ How do you handle partitions?
├─ How do you sync data?
└─ What SLA is realistic?
```
